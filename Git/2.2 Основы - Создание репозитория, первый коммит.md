## 1. Что такое репозиторий

**Репозиторий** — это папка проекта с скрытой директорией `.git/` внутри. Команда `git init` создаёт **пустой репозиторий** — появляется `.git/` и Git начинает отслеживать проект. Пустой означает что истории коммитов ещё нет.

`.git/` — это не копии твоих файлов. Здесь Git хранит историю всех изменений в своём собственном формате — сжатом и оптимизированном. Твои файлы в папке проекта — это то с чем ты работаешь прямо сейчас. `.git/` — это вся история этих файлов с момента первого коммита. Удалишь `.git/` — Git перестанет отслеживать проект, файлы останутся но история исчезнет.

```
my-project/
├── .git/        ← вся история проекта (не трогай руками)
├── main.go
└── README.md
```

Тебе не нужно заходить туда и что-то менять вручную — Git управляет этой директорией сам через команды.

Родительская директория (папка в которой лежат репозитории) сама по себе репозиторием не является:

```
~/Tools/                    ← родительская директория (не репозиторий)
├── devops-notes/           ← репозиторий (есть .git/)
│   └── .git/
├── work-project/           ← репозиторий (есть .git/)
│   └── .git/
└── open-source/            ← репозиторий (есть .git/)
    └── .git/
```

Репозитории могут лежать в совершенно разных местах на машине — в разных родительских директориях — они всё равно остаются отдельными репозиториями. Git смотрит только на наличие `.git/` внутри папки, а не на то где она находится.

> Подробное устройство `.git/` разберём в отдельной теме.

## 2. Три зоны Git

Git использует трёхступенчатую систему сохранения изменений — это одна из важнейших особенностей Git. Логически проект разделён на три зоны:

**1. Рабочая директория (Working Directory)**
Файлы которые сейчас лежат в проекте — то что ты видишь в папке проекта прямо сейчас.

**2. Индекс (Staging Area / Index)**
Промежуточная зона. Сюда попадают файлы после `git add` — это список изменений подготовленных к записи в историю. Можно изменить 10 файлов но добавить в индекс только 3 — именно они войдут в следующий коммит.

**3. Репозиторий (Repository)**
Здесь хранится вся история проекта навсегда. Сюда попадают изменения после `git commit`.

> Индекс и Репозиторий — это логическое разделение. Физически оба хранятся внутри `.git/`.

### Путь файла через три зоны

Возьмём файл `app.py` — он будет нашим примером на протяжении всей темы:

```
app.py создан    →  Рабочая директория  (Git видит но не отслеживает)
git add app.py   →  Индекс             (подготовлен к коммиту)
git commit       →  Репозиторий        (сохранён в истории навсегда)
```

В следующих разделах мы пройдём этот путь шаг за шагом.

## 3. Создание репозитория — git init

Чтобы начать отслеживать изменения в проекте нужно создать репозиторий:

```bash
# Перейти в папку проекта
cd ~/projects/my-project

# Инициализировать репозиторий
git init
# Initialized empty Git repository in ~/projects/my-project/.git/
```

После выполнения команды в папке проекта появится скрытая директория `.git/` — с этого момента Git начинает отслеживать изменения.

```bash
# Убедиться что .git/ создана
ls -la
# drwxr-xr-x  .git/
```

**Как отказаться от Git в проекте:**

Если нужно прекратить использование Git — достаточно просто удалить папку `.git/`:

```bash
rm -rf .git/
# Репозиторий удалён, файлы проекта остались нетронутыми
```

## 4. Просмотр состояния — git status

`git status` — одна из самых часто используемых команд. Показывает текущее состояние проекта глазами Git: какие файлы изменены, какие добавлены в индекс, какие не отслеживаются.

```bash
git status
```

Пример вывода когда есть новые файлы:

```
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        README.md
        main.go

nothing added to commit but untracked files present
```

**Untracked files** — файлы которые есть в рабочей директории но отсутствуют в индексе. Git видит их но не отслеживает.

После коммита при отсутствии новых изменений `git status` выведет:

```
On branch main
nothing to commit, working tree clean
```

Это означает что рабочая директория, индекс и репозиторий полностью соответствуют друг другу — всё закоммичено.

## 5. Добавление файлов в индекс — git add

Когда создаёшь новый файл — Git о нём ничего не знает (`untracked`). Чтобы Git начал отслеживать файл и подготовил его к сохранению используется команда `git add`:

```bash
# Добавить конкретный файл
git add README.md

# Добавить несколько файлов
git add README.md main.go

# Добавить все файлы в текущей директории
git add .
```

После `git add` файл становится **проиндексированным** — он переходит в состояние/статус `staged` (термин из документации Git). Это означает что Git запомнил изменения этого файла и включит их в следующий коммит. В терминале это состояние отображается как `Changes to be committed`.

Физически индекс — это один бинарный файл `.git/index` в который Git записывает список файлов и их состояния.

Проверить статус можно через `git status`:

```
Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
        new file:   README.md
        new file:   main.go
```

## 6. Создание коммита — git commit

Коммит — это окончательная запись изменений из индекса в репозиторий. После коммита изменения сохраняются в истории Git навсегда.

> **Важно:** перед первым коммитом обязательно должны быть настроены `user.name` и `user.email` через `git config` — иначе команда откажется работать. Это мы делали в теме `2.1`.

```bash
git commit
```

При запуске без флагов откроется текстовый редактор (тот что настроен в `core.editor`) где нужно ввести описание изменений. Git сам перечислит изменения в редакторе — строки начинающиеся с `#` — но при сохранении эти строки будут удалены, в историю попадёт только твой текст.

Чаще используют флаг `-m` чтобы написать сообщение сразу:

```bash
git commit -m "Initial commit"
```

После успешного коммита Git выдаст подтверждение с хешем:

```
[main (root-commit) a1b2c3d] Initial commit
 2 files changed, 10 insertions(+)
 create mode 100644 README.md
 create mode 100644 main.go
```

`a1b2c3d` — это сокращённый SHA-1 хеш коммита. По этому идентификатору можно просмотреть изменения, узнать автора или восстановить файлы на определённый момент времени.
