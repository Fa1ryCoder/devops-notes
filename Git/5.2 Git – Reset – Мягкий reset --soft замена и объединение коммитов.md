# Reset --soft: замена и объединение коммитов

`git reset --soft` — самый безопасный из трёх режимов reset. Он двигает только историю, не трогая ни индекс, ни файлы на диске, поэтому потерять данные этой командой практически невозможно.

## Механика

При выполнении `git reset --soft <commit>` происходит только одно: указатель текущей ветки (а вместе с ним и HEAD) перемещается на `<commit>`. Индекс и рабочая директория при этом не меняются вообще — команда их не касается. Сам `--soft` не выводит никакого сообщения, в отличие от `--mixed` и `--hard`: с точки зрения файлов и индекса действительно ничего не произошло.

Раз индекс остался прежним, а HEAD «уехал» назад, между ними образуется разница: в индексе лежит содержимое, которое соответствовало старому, более новому коммиту, а HEAD теперь указывает на более ранний. Эту разницу git показывает как staged-изменения — уже готовые к коммиту, без повторного `git add`.

```bash
git reset --soft <commit>
```

Для сравнения — `--hard` идёт дальше: он сбрасывает не только HEAD, но и индекс, и рабочую директорию, поэтому разница между коммитами не остаётся видна как staged, а исчезает целиком.

| Режим | HEAD | Индекс | Рабочая директория |
|---|---|---|---|
| `--soft` | перемещается | не меняется (изменения staged) | не меняется |
| `--hard` | перемещается | сбрасывается | сбрасывается (данные удаляются) |

## Замена последнего коммита

Типичный случай — коммит уже сделан, но в нём опечатка, забытый файл или лишний кусок кода.

```bash
git reset --soft HEAD~1
# правите код, добавляете забытое
git add .
git commit -m "Исправленный коммит"
```

Коммит пропадает из истории, а все его изменения остаются staged — их можно доработать и закоммитить заново.

## Объединение коммитов

Второй частый сценарий — несколько мелких коммитов в ветке, которые не нужны в истории по отдельности: опечатки, промежуточные сохранения.

```bash
git reset --soft HEAD~5
git commit -m "Реализована фича X"
```

HEAD перемещается на пять коммитов назад, а изменения всех пяти сразу оказываются staged — единым набором правок, из которого один `git commit` собирает аккуратный коммит вместо пяти.

## Практика: закрепляем на тестовом репозитории

Упражнение повторяет оба сценария выше и на каждом шаге показывает, что именно меняется — через `git log --graph` (граф коммитов и куда указывает HEAD) и `git status` (что произошло с индексом). Выполняйте в своём тестовом репозитории.

### Шаг 1. Три обычных коммита

```bash
echo "line1" > file.txt && git add file.txt && git commit -m "commit A"
echo "line2" >> file.txt && git add file.txt && git commit -m "commit B"
echo "line3" >> file.txt && git add file.txt && git commit -m "commit C"
git log --oneline --graph --decorate
```

Должно получиться три коммита подряд, HEAD и master указывают на `commit C`:

```
* 982de08 (HEAD -> master) commit C
* 3400219 commit B
* 4d08690 commit A
```

### Шаг 2. Замена последнего коммита

```bash
git reset --soft HEAD~1
git log --oneline --graph --decorate
git status --short
```

Коммита `commit C` в графе больше нет — HEAD и master теперь на `commit B`. А `git status --short` покажет `M  file.txt`: изменения из «пропавшего» коммита никуда не делись, они staged.

```
* 3400219 (HEAD -> master) commit B
* 4d08690 commit A
M  file.txt
```

Закоммитьте их заново — например, с более точным сообщением:

```bash
git commit -m "commit C (исправленный)"
git log --oneline --graph --decorate
```

Граф снова из трёх коммитов, но третий — новый, с другим хэшем:

```
* e6f3993 (HEAD -> master) commit C (исправленный)
* 3400219 commit B
* 4d08690 commit A
```

### Шаг 3. Объединяем несколько мелких коммитов

Сделайте ещё три «грязных» коммита поверх текущей истории:

```bash
echo "fix1" >> file.txt && git add file.txt && git commit -m "правка 1"
echo "fix2" >> file.txt && git add file.txt && git commit -m "правка 2"
echo "fix3" >> file.txt && git add file.txt && git commit -m "правка 3"
git log --oneline --graph --decorate
```

```
* 81ab364 (HEAD -> master) правка 3
* 5670e1d правка 2
* efdb877 правка 1
* e6f3993 commit C (исправленный)
* 3400219 commit B
* 4d08690 commit A
```

Теперь объедините все три коммита в один:

```bash
git reset --soft HEAD~3
git log --oneline --graph --decorate
git status --short
git diff --staged --stat
```

В графе три последних коммита исчезли, HEAD вернулся на `commit C (исправленный)`. `git status --short` покажет тот же файл staged, а `git diff --staged --stat` — что в индексе сразу сумма изменений всех трёх коммитов:

```
* e6f3993 (HEAD -> master) commit C (исправленный)
* 3400219 commit B
* 4d08690 commit A
M  file.txt
 file.txt | 3 +++
 1 file changed, 3 insertions(+)
```

Завершите одним коммитом:

```bash
git commit -m "Реализована фича X"
git log --oneline --graph --decorate
```

```
* 6afb5c0 (HEAD -> master) Реализована фича X
* e6f3993 commit C (исправленный)
* 3400219 commit B
* 4d08690 commit A
```

Три мелких коммита в истории заменились одним осмысленным — это и есть весь смысл `reset --soft` в связке с ручным коммитом.
