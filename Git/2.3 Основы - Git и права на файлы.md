## 1. Разбор вывода git commit

После первого коммита Git выдаёт следующее:

```
[main (root-commit) a1b2c3d] Initial commit
 2 files changed, 10 insertions(+)
 create mode 100644 README.md
 create mode 100644 app.py
```

Разберём каждую строку:

| Часть вывода | Что означает |
|---|---|
| `main` | Ветка в которую сделан коммит |
| `root-commit` | Первый коммит в репозитории — у него нет родителя |
| `a1b2c3d` | Сокращённый SHA-1 хеш коммита |
| `Initial commit` | Сообщение коммита |
| `2 files changed` | Количество изменённых файлов |
| `10 insertions(+)` | Количество добавленных строк |
| `create mode 100644` | Файл создан с правами 100644 |

## 2. Как Git хранит права на файлы

### Зачем вообще хранить бит исполняемости в Git

Казалось бы — можно скачать файл и сделать `chmod +x` вручную. Но на практике это создаёт проблемы:

**Команда из 10 человек** — каждый клонирует репозиторий и каждому нужно вручную делать `chmod +x deploy.sh`. Кто-то забудет — скрипт не запустится. Если бит исполняемости хранится в Git — при клонировании файл сразу готов к запуску у всех.

**CI/CD пайплайн** — GitLab Runner или GitHub Actions клонирует репозиторий и запускает скрипты автоматически. Там нет человека который сделает `chmod +x`. Если бит не сохранён в Git — пайплайн упадёт с ошибкой `Permission denied`.

**Docker образ** — в `Dockerfile` часто копируют скрипты из репозитория и запускают их. Если бит исполняемости не сохранён — скрипт не запустится внутри контейнера.

Число перед именем файла в индексе состоит из двух частей:

```
100644
^^^---  тип объекта (100 = обычный файл)
   ^^^  права доступа (644 = не исполняемый)
```

**Основные типы объектов:**
- `100` — обычный файл
- `120` — символическая ссылка (symlink)

Остальные типы (`040` — директории, `160` — подмодули) существуют, но к правам доступа отношения не имеют.

**Права доступа:**

В отличие от полноценных прав в Unix (чтение, запись, выполнение для владельца, группы и остальных) — Git сохраняет только **один бит — является ли файл исполняемым**.

В репозитории Git существует всего два режима прав:

| Код | Права | Описание |
|-----|-------|----------|
| `644` | `-rw-r--r--` | Файл не является исполняемым |
| `755` | `-rwxr-xr-x` | Файл является исполняемым |

Посмотреть права файлов в индексе можно командой:

```bash
git ls-files --stage
# 100644 a1b2c3d 0    README.md
# 100644 b2c3d4e 0    app.py
```

## 3. Отслеживание изменений прав

Для Git изменение прав доступа — такое же существенное изменение как и правка содержимого файла. Если в Unix-системе изменить права через `chmod`, `git status` пометит файл как изменённый:

```bash
# Сделали файл исполняемым
chmod +x app.py

# Git видит изменение
git status
# Changes not staged for commit:
#   modified: app.py

# Посмотреть что изменилось
git diff
# old mode 100644
# new mode 100755
```

Такое изменение можно добавить в индекс и зафиксировать в коммите:

```bash
git add app.py
git commit -m "Make app.py executable"
```
