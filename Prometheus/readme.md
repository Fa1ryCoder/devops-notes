Начнем с определения Prometheus. Что такое Prometheus?
"Prometheus" — это система мониторинга, которая собирает и хранит метрики как временные ряды, используя уникальную многомерную модель данных с labels (тегами). Она работает по pull-модели (сама опрашивает targets по http с помощью config где указаны nodes), предоставляет мощный декларативный язык запросов PromQL для агрегации и анализа, имеет встроенный механизм алертинга и активно используется в cloud-native стеках (Kubernetes)
Все равно остаются вопросы по определению. Метрика, временной ряд и т.д. Что же все это такое?

"Метрика (metrics)" - это измерение какого либо параметра системы во времени. Проще: это число которое, Prometheus регулярно запысывает. Например:
    Загрузка CPU = 72%
    Свободная память = 1.3 GB
    Количество HTTP-запросов = 152
    температура сервера = 45°C
Важно отметить что Prometheus оперирует сырыми числами(row data) и не хранит информацию о единицах измерения. Чтобы превратить его в осмысленную метрику (например, в процент загрузки или скорость запросов в секунду), данные необходимо обработать с помощью PromQL(Это уже задача специалиста кто создает метрики). Изначально данные будут выглядить вот так: 0.72 (ratio), 1395864371 (bytes), 1003152, 45000.
В Prometheus метрика выглядит примерно так:
    node_cpu_seconds_total{cpu="0",mode="idle"} 12345.6
Здесь:
    - node_cpu_seconds_total = имя метрики
    - {cpu="0",mode="idle"} = метки (labels)
    - 12345.6 = значение

"Временной ряд (time series)" - это история значения метрики во времени. То есть Prometheus не просто хранит одно число. Он хранит: 
    время --> значение. 
Например:
    12:00 --> CPU = 40%
    12:01 --> CPU = 55%
    12:02 --> CPU = 72%
    12:03 --> CPU = 38%
Это и есть временной ряд. Временный ряды хранятся локально на диске, можно опционально интегрировать с удалёнными системами хранения. Он собирает данные(метрики во времени), примерно, ~2 часа и потом запечатывает в блок. Пример блока:
    /01KGPQB344WPSFXVM8F0A1XJCR
Важно: Мы не собираем данные когда пишем, например, метрику: node_cpu_seconds_total{mode="idle"}[5m]. Мы запрашиваем собранные данные с помощью PromQL. PromQL это язык запросов, а не сбора!

"Теги (labels)" - это пары ключ="значение", которые прикрепляются к метрике для добавления контекста. Метрики нужны для:
    Дифференциация: Позволяют отличить метрику одного сервера от другого (instance="web-01" vs instance="web-02").
    Агрегация: Позволяют посчитать общую сумму запросов по всему региону или конкретному приложению, используя фильтры в PromQL
    Динамичность: Тебе не нужно создавать метрику http_requests_total_server1, ты создаешь одну метрику http_requests_total и разделяешь данные метками.
