# ТС ПИоТ для ФР Пирит — установка через Ansible

## Структура проекта

```
~/ansible-cashregisters/
├── ansible.cfg
├── inventory/
│   └── hosts.yml                          ← список касс
├── group_vars/
│   └── cashregisters.yml                  ← пароль root
├── host_vars/                              ← индивидуальные пароли (если отличаются)
└── playbooks/
    ├── tsipiot_pirit.yml                  ← плейбук
    └── templates/
        └── esmmanager.ini.j2             ← шаблон конфига ESM
```

---

## Что нужно подготовить перед запуском

1. **ansible.cfg** — должен лежать в корне проекта `~/ansible-cashregisters/`. Создавался в Документе 2.

2. **`.deb` пакеты** — положить в `/tmp/packages/` на control node:
   - `esm_1.6.2.1_amd64.deb`
   - `esm-lm-controller_1.6.2.1_amd64.deb`
   - `esm-csi-dkkt.deb`

3. **Шаблон** `esmmanager.ini.j2` — должен лежать в `playbooks/templates/`.

4. **Инвентарь** — добавить нужные кассы в `inventory/hosts.yml`.

---

## Переменные плейбука

Все ключевые пути и параметры вынесены в блок `vars` в начале плейбука — менять нужно только там, не трогая логику задач.

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `allowed_pos_versions` | `["4.6.304-10", "5.304.10"]` | Допустимые версии artix-pos / artix-sst-sco |
| `deb_local_dir` | `/tmp/packages` | Директория с `.deb` пакетами на control node |
| `deb_src_dir` | `/opt/tsipiot/packages` | Директория куда пакеты копируются на кассе |
| `esm_conf_dest` | `/linuxcash/cash/conf/ncash.ini.d/puppet/~esmmanager.ini` | Путь назначения для конфига ESM на кассе |
| `crpt_ini_path` | `/linuxcash/cash/conf/ncash.ini.d/puppet/crpt.ini` | Путь к `crpt.ini` на кассе |

## Что делает плейбук (блок за блоком)

### Блок 1 — Определение типа кассы и проверка версии

Сначала собираются факты об установленных пакетах через `package_facts`. Затем плейбук определяет тип кассы:

- Если установлен `artix-pos` — касса типа **РМК**
- Если установлен `artix-sst-sco` — касса типа **КСО**

Если ни один из пакетов не найден или версия не входит в список допустимых (`4.6.304-10` или `5.304.10`) — касса **пропускается** через `meta: end_host`. Перед пропуском в консоль выводится понятное сообщение с причиной, чтобы при раскатке на большую сеть было видно какие кассы отсеялись и почему. Остальные кассы из группы при этом продолжают выполняться.

### Блок 2 — Обновление artix-comproxy

Обновляет пакет `artix-comproxy` через `aptitude install`. После обновления версия пакета проверяется через `dpkg-query` — это быстрее и точнее, чем повторный вызов `package_facts`. Если версия оказалась ниже `1.15-62` — касса пропускается с сообщением об этом. Версия `1.15-62` и выше считается допустимой (проверяется на строгое "меньше").

### Блок 3 — Копирование .deb пакетов на кассу

Создаёт директорию `/opt/tsipiot/packages/` на кассе если её нет, затем копирует три `.deb` пакета с control node (`/tmp/packages/`) на кассу. Это избавляет от необходимости вручную загружать пакеты на каждую машину.

### Блок 4 — Установка .deb пакетов

Устанавливает три пакета через нативный модуль `apt` с параметром `deb:` — это идемпотентно (повторный запуск не переустановит уже стоящие пакеты). Порядок установки строго соблюдается:

```
esm → esm-lm-controller → esm-csi-dkkt
```

Если хотя бы один пакет установился или обновился — через `notify` ставится отложенный перезапуск `comproxy`.

### Блок 5 — Сертификаты

Копирует четыре сертификата из директорий `/etc/esp/` в `/usr/local/share/ca-certificates/`. Результат копирования сохраняется в переменную `certs_copied`. Команда `update-ca-certificates` запускается **только если хотя бы один сертификат реально изменился** (`when: certs_copied.changed`) — на слабом железе касс это экономит 3–5 секунд при повторных прогонах.

### Блок 6 — Чтение crpt.ini и парсинг значений

Проверяет наличие файла `crpt.ini` на кассе. Если файл есть — читает его через модуль `slurp` (файл передаётся в base64, потом декодируется). Из секции `[LMCHZ]` извлекаются три значения через регулярные выражения:

- `url` — адрес сервиса ЛМЧЗ (например `http://10.16.7.21:5995`)
- `user` — имя пользователя
- `password` — пароль

Из `url` отдельной задачей вытаскивается только IP/хост — протокол (`http://`) и порт (`:5995`) отбрасываются. Если `crpt.ini` не найден или в нём нет нужных строк — шаг пропускается, секция `[ESM.LMCHZ]` в конфиг не добавляется.

### Блок 7 — Генерация ~esmmanager.ini

Генерирует конфиг из шаблона `esmmanager.ini.j2` и кладёт его на кассу. Шаблон содержит статичную часть (настройки плагинов маркированной продукции) и динамическую секцию `[ESM.LMCHZ]` — она добавляется только если `crpt.ini` был найден и успешно распарсен. Если конфиг изменился — через `notify` ставится отложенный перезапуск `comproxy`.

### Handler — перезапуск comproxy

`comproxy` перезапускается **только один раз в конце плейбука** и **только если** было реальное изменение — установились пакеты или обновился конфиг. Если плейбук запущен повторно и ничего не изменилось — перезапуска не будет. Это исключает случайное прерывание связи с ФР Пирит в середине рабочего дня.

## Запуск

Запуск на всей группе касс:
```bash
ansible-playbook playbooks/tsipiot_pirit.yml -i inventory/hosts.yml
```

Запуск на одной кассе (для теста перед раскаткой):
```bash
ansible-playbook playbooks/tsipiot_pirit.yml -i inventory/hosts.yml --limit rmk-161
```

Проверка без реального применения (dry run):
```bash
ansible-playbook playbooks/tsipiot_pirit.yml -i inventory/hosts.yml --check
```
