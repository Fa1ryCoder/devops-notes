# 5.4 Git – Reset – Смешанный reset (без флагов), сравнение видов reset

Смешанный reset (`--mixed`) — режим, который Git применяет по умолчанию, если при вызове `git reset` не указан флаг `--soft` или `--hard`. Он перемещает указатель текущей ветки на выбранный коммит и обновляет индекс в соответствии с этим коммитом, но не трогает рабочую директорию — как и `--soft`.

## Сравнение режимов reset

| Режим | Ветка (HEAD) | Индекс | Рабочая директория |
|---|---|---|---|
| `--soft` | перемещается | не изменяется | не изменяется |
| `--mixed` (по умолчанию) | перемещается | обновляется | не изменяется |
| `--hard` | перемещается | обновляется | обновляется, несохранённые изменения теряются |

Отсюда и разница в применении:
- `--soft` экономит шаг, когда нужен коммит со всеми изменениями как есть — например, объединить несколько последних коммитов в один или просто переписать сообщение коммита.
- `--mixed` — когда состав коммита нужно менять, а не просто повторить прежний целиком.

Есть практический нюанс, который легко упустить: если после `--soft` изменено несколько файлов, а в коммит нужно включить не все — простое добавление нужного файла через `git add` не поможет, остальные файлы уже в индексе с момента reset и всё равно попадут в коммит. Их нужно явно убрать из индекса — `git reset <файл>`. После `--mixed` в той же ситуации в коммит попадёт только то, что добавлено явно.

**Коротко:** `--soft` отбрасывает последний коммит, `--mixed` — последний коммит и индексацию (`add`), `--hard` — последний коммит, индексацию и любые изменения в рабочей директории. По содержимому файлов `--hard` эквивалентен не голому `git checkout HEAD` (тот без явного пути вообще ничего не делает), а `git checkout HEAD -- .` или, по-современному, `git restore --staged --worktree .`

## Основные возможности и применение

1. **Переделка последних коммитов.** После смешанного reset на более старый коммит файлы в рабочей директории остаются в том виде, в котором были до reset, но Git помечает их как изменённые — они теперь отличаются от только что сброшенного индекса. Это удобно, когда нужно не просто отменить коммит, а заново решить, какие изменения войдут в новый: индекс свободен, и в него можно заново добавить нужное — целиком или частично — командой `git add`.

2. **Очистка индекса (unstaging).** Вызов `git reset` без аргументов (то же самое, что `git reset HEAD`) сбрасывает индекс до состояния текущего коммита. Ветка при этом никуда не перемещается, а содержимое файла не затрагивается — меняется только его статус в индексе. По сути `git reset` — антипод `git add`.

3. **Сброс по конкретным путям.** В отличие от `--soft` и `--hard`, смешанный reset умеет работать с отдельными файлами. Команда `git reset index.html` уберёт из индекса изменения только этого файла, не затронув остальные проиндексированные файлы.
