# Что такое Docker и зачем он нужен?

## 1. Что такое Docker

**Docker** — это платформа для запуска приложений в контейнерах: изолированных, лёгких окружениях, которые содержат приложение вместе со всеми его зависимостями. Контейнеры работают поверх общего ядра хост-ОС.

Важно различать два понятия, которые часто путают:
- **Docker** — конкретный инструмент/платформа (демон `dockerd`, CLI, формат образов, Docker Hub и т.д.), с которого всё начиналось.
- **Контейнеризация** — сам подход к изоляции приложений на уровне ОС. Docker — самая известная реализация, но не единственная (есть containerd, Podman, CRI-O — все они умеют работать с тем же стандартизированным форматом образов OCI, который вырос из Docker).

Из чего состоит Docker как система:
- **Docker Engine (dockerd)** — демон, который на хосте реально собирает образы, запускает и останавливает контейнеры, управляет сетями и volume'ами.
- **Docker CLI (Command Line Interface)** — интерфейс управления демоном `dockerd`. Это команда `docker`, которая сама ничего не исполняет, а отправляет команды демону через его API (по умолчанию через Unix-сокет `/var/run/docker.sock`). Вся реальная работа — сборка образов, запуск контейнеров — происходит в демоне.
- **Образ (image)** — неизменяемый шаблон, который включает в себя все файлы, бинарники, библиотеки и конфигурации, необходимые для запуска контейнера.
- **Контейнер (container)** — запущенный экземпляр образа: живой процесс со своим изолированным пространством имён, файловой системой и ресурсами.
- **Registry (например, Docker Hub)** — хранилище готовых образов, откуда их можно скачать (`docker pull`) или куда загрузить свой (`docker push`).

## 2. Какие проблемы решает Docker

**Проблема «На моем компьютере всё работает»**
Раньше различие в версиях системных библиотек, зависимостей или ОС приводило к ошибкам при переносе кода. Docker упаковывает приложение вместе со всеми зависимостями и окружением в единый неизменяемый образ, гарантируя идентичное поведение системы на любой машине.

**Высокое потребление ресурсов виртуальными машинами**
Классическая виртуализация требует запуска отдельной полноценной ОС для каждого сервиса, что расходует гигабайты RAM и ресурсы CPU. Контейнеры делят ядро хостовой ОС, запускаясь как изолированные процессы с минимальной нагрузкой на железо.

**Медленный и сложный запуск сервисов**
Разворачивание баз данных, брокеров сообщений и других окружений локально часто требует долгой ручной настройки. Контейнер запускается за доли секунды одной командой (например, `docker run` или через `docker-compose`).

**Сложность масштабирования и микросервисной архитектуры**
Запуск десятков связанных сервисов вручную превращается в ад администрирования. Docker упрощает изолированный запуск каждого микросервиса и служит стандартом для систем оркестрации (Kubernetes).

**Конфликты версий и окружений**
Если двум проектам на одном сервере требуются разные версии Python, Node.js или системных библиотек, в обычной ОС возникают конфликты. Docker изолирует приложения друг от друга в файловой системе и сети.

## 3. Частые вопросы по этой теме

- **"Чем контейнер отличается от виртуальной машины?"** — контейнер шарит ядро хоста и изолируется через namespaces/cgroups, VM виртуализирует железо и грузит своё ядро. Отсюда разница в весе (мегабайты vs гигабайты) и скорости старта (секунды/миллисекунды vs минуты).
- **"Зачем Docker, если есть Ansible/Puppet?"** — Ansible настраивает существующую машину (может давать дрифт со временем, зависит от исходного состояния), Docker собирает неизменяемый образ с нуля по Dockerfile — воспроизводимость сильнее.
- **"Что решает проблему 'у меня работает'?"** — то, что зависимости и рантайм зафиксированы внутри образа, а не полагаются на то, что стоит на хост-машине.
- **"Правда ли что Docker — это настоящая виртуализация?"** — нет, это виртуализация на уровне ОС (OS-level virtualization), а не аппаратная виртуализация как у гипервизоров (VMware, KVM, Hyper-V).
- **"Можно пример, когда без Docker было бы плохо?"** — держать на одном сервере два приложения с разными и несовместимыми версиями системной библиотеки (например, разные ABI-несовместимые версии libssl) — без изоляции это конфликт, с контейнерами — два независимых образа со своими зависимостями.
