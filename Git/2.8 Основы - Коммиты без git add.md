В предыдущих темах мы использовали двухступенчатый процесс: `git add` → `git commit`. Но в Git есть способы ускорить этот процесс и обойтись без явного `git add`.

---

## 1. Флаг -a — автоматическое индексирование

Флаг `-a` (`--all`) заставляет Git автоматически добавить все изменённые отслеживаемые файлы в индекс и сразу создать коммит — объединяет `git add` и `git commit` в одну операцию:

```bash
git commit -a -m "fix: исправить опечатку в конфиге"

# Или сокращённо
git commit -am "fix: исправить опечатку в конфиге"
```

**Важное ограничение:** флаг `-a` игнорирует новые (`untracked`) файлы которые ещё не были добавлены в систему контроля версий. Если создал новый файл — этот способ для него не сработает:

```bash
touch new-file.py
git commit -am "add new file"
# new-file.py НЕ попадёт в коммит — он untracked
```

**Когда использовать:** удобно когда вносишь правки только в уже существующие файлы и уверен что все изменения формируют один логичный коммит.

---

## 2. Коммит конкретных файлов по пути

Можно указать Git какие именно файлы нужно закоммитить прямо сейчас — даже если в рабочей директории есть другие изменения:

```bash
git commit auth.py -m "fix: исправить валидацию токена"
# Только auth.py попадёт в коммит
# Остальные изменения в проекте остаются нетронутыми
```

**Ограничение:** как и флаг `-a`, этот метод работает только для уже отслеживаемых файлов. Попытка закоммитить новый файл таким способом завершится ошибкой.

**Когда использовать:** когда в проекте ведётся параллельная работа над несколькими задачами и нужно срочно зафиксировать одно конкретное исправление не затрагивая остальной код.

По сути это альтернатива `git commit -am` — оба способа пропускают `git add` и не работают с `untracked` файлами. Разница только в охвате:

```bash
# git commit -am — все отслеживаемые файлы
git commit -am "fix: исправления"

# git commit <файл> — только конкретный файл, остальные изменения не трогает
git commit auth.py -m "fix: исправить валидацию"
```

Оба способа не работают с новыми (`untracked`) файлами — это сделано специально для безопасности, чтобы разработчик случайно не добавил в репозиторий лишнее: временные файлы, результаты сборки, логи. Git требует явного подтверждения через первый `git add` для включения нового файла в отслеживание.

---

## 3. Алиас для коммита всех изменений

В Git нет встроенного флага который бы добавлял и новые файлы и изменения в старых за один шаг. Но это можно реализовать через алиас:

```bash
# Алиас который сначала делает git add -A, потом git commit
git config --global alias.ca "!git add -A && git commit"

# Использование
git ca -m "feat: добавить авторизацию"
```

**Разница между `git add .` и `git add -A` в алиасе:**
- `git add .` — добавит изменения только из текущей директории и вложенных
- `git add -A` — добавит все изменения во всём проекте независимо от того в какой папке находишься

> **Осторожно:** не злоупотребляй такими алиасами, сваливая все изменения в один большой коммит с невнятным описанием. Используй только если уверен что все изменения логически формируют один хороший коммит.
