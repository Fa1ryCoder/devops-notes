## 1. Что такое репозиторий

**Репозиторий** — это папка проекта с скрытой директорией `.git/` внутри. Команда `git init` создаёт **пустой репозиторий** — появляется `.git/` и Git начинает отслеживать проект. Пустой означает что истории коммитов ещё нет.

`.git/` — это не копии твоих файлов, а история всех изменений в собственном формате Git — сжатом и оптимизированном. Файлы в папке проекта — то, с чем ты работаешь прямо сейчас; `.git/` хранит всё, что было с ними с момента первого коммита. Удалишь `.git/` — Git перестанет отслеживать проект, файлы останутся, но история исчезнет.

```
my-project/
├── .git/        ← вся история проекта (не трогай руками)
├── main.go
└── README.md
```

Тебе не нужно заходить туда и что-то менять вручную — Git управляет этой директорией сам через команды.

Родительская директория (папка в которой лежат репозитории) сама по себе репозиторием не является:

```
~/Tools/                    ← родительская директория (не репозиторий)
├── devops-notes/           ← репозиторий (есть .git/)
│   └── .git/
├── work-project/           ← репозиторий (есть .git/)
│   └── .git/
└── open-source/            ← репозиторий (есть .git/)
    └── .git/
```

Репозитории могут лежать в совершенно разных местах на машине — в разных родительских директориях — они всё равно остаются отдельными репозиториями. Git смотрит только на наличие `.git/` внутри папки, а не на то где она находится.

## 2. Создание репозитория — git init

Чтобы начать отслеживать изменения в проекте нужно создать репозиторий:

```bash
# Перейти в папку проекта
cd ~/projects/my-project

# Инициализировать репозиторий
git init
# Initialized empty Git repository in ~/projects/my-project/.git/
```

После этой команды в папке проекта появляется `.git/`.

**Как отказаться от Git в проекте:**

Если нужно прекратить использование Git — достаточно просто удалить папку `.git/`:

```bash
rm -rf .git/
```

## 3. Просмотр состояния — git status

`git status` — одна из самых часто используемых команд. Показывает текущее состояние проекта глазами Git: какие файлы изменены, какие добавлены в индекс, какие не отслеживаются.

```bash
git status
```

Пример вывода когда есть новые файлы:

```
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        README.md
        main.go

nothing added to commit but untracked files present
```

**Untracked files** — файлы которые есть в рабочей директории но отсутствуют в индексе. Git видит их но не отслеживает.

После коммита при отсутствии новых изменений `git status` выведет:

```
On branch main
nothing to commit, working tree clean
```

Это означает что рабочая директория, индекс и репозиторий полностью соответствуют друг другу — всё закоммичено.

## 4. Добавление файлов в индекс — git add

Когда создаёшь новый файл — Git о нём ничего не знает (`untracked`). Чтобы Git начал отслеживать файл и добавил его в индекс используется команда `git add`:

```bash
# Добавить конкретный файл
git add README.md

# Добавить несколько файлов
git add README.md main.go

# Добавить все файлы в текущей директории
git add .
```

После `git add` файл переходит в статус `staged` (термин из документации Git) — Git запомнил его изменения и включит их в следующий коммит. В выводе `git status` это отображается как `Changes to be committed`.

Физически индекс — это один бинарный файл `.git/index`, где на каждый файл — одна запись: **путь файла и хеш содержимого**. Подробнее этот механизм разобран в теме `2.x Основы - Внутреннее устройство .git`. `git add` создаёт или перезаписывает эту запись. Хеш висит без изменений, пока не сделаешь `git add` заново — а если к этому моменту реальное содержимое файла разошлось с хешем в индексе, `git status` покажет файл как `modified`.

Если файлов несколько — у каждого своя независимая запись, и `git add` обновляет только ту, что указал явно, остальные не трогает. `git commit` берёт индекс целиком, как единый снимок, а не выбранные файлы: в коммит попадёт то, что записано в индексе на этот момент для каждого файла. Сам индекс при этом не меняется и не очищается — если какой-то файл менял, но не застейджил, эти изменения просто останутся `modified` и дождутся следующего `git add`.

Проверить статус можно через `git status`:

```
Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
        new file:   README.md
        new file:   main.go
```

## 5. Создание коммита — git commit

Коммит — это окончательная запись изменений из индекса в репозиторий. После коммита изменения сохраняются в истории Git навсегда.

> **Важно:** перед первым коммитом обязательно должны быть настроены `user.name` и `user.email` через `git config` — иначе команда откажется работать.

```bash
git commit
```

При запуске без флагов откроется текстовый редактор (тот что настроен в `core.editor`) где нужно ввести описание изменений. Git сам перечислит изменения в редакторе — строки начинающиеся с `#` — но при сохранении эти строки будут удалены, в историю попадёт только твой текст.

Чаще используют флаг `-m` чтобы написать сообщение сразу:

```bash
git commit -m "Initial commit"
```

После успешного коммита Git выдаст подтверждение с хешем:

```
[main (root-commit) a1b2c3d] Initial commit
 2 files changed, 10 insertions(+)
 create mode 100644 README.md
 create mode 100644 main.go
```

`a1b2c3d` — это сокращённый SHA-1 хеш коммита. По этому идентификатору можно просмотреть изменения, узнать автора или восстановить файлы на определённый момент времени.
