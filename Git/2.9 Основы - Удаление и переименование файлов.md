В Git удаление и переименование файлов — это такие же изменения проекта как добавление или модификация. Они тоже должны пройти через индекс прежде чем попасть в репозиторий.

---

## 1. Удаление файлов

Существует два способа удалить файл из репозитория.

### Ручное удаление (два шага)

```bash
# Шаг 1 — удаляем файл физически
rm app.py

# git status покажет что файл удалён, но изменение ещё не в индексе
git status
# Changes not staged for commit:
#   deleted: app.py

# Шаг 2 — добавляем факт удаления в индекс
git add app.py    # несмотря на то что файла уже нет — Git добавит факт удаления

git commit -m "remove app.py"
```

### Команда git rm

`git rm` выполняет оба шага за один — удаляет файл с диска и добавляет факт удаления в индекс:

```bash
git rm app.py
git commit -m "remove app.py"
```

### Флаги git rm

```bash
# Удалить директорию рекурсивно
git rm -r configs/

# Удалить из индекса но оставить файл на диске
git rm --cached .idea/workspace.xml

# Принудительное удаление файла с незакоммиченными изменениями
git rm -f app.py
```

**`--cached`** — прекращает отслеживание файла но оставляет его в рабочей директории. Применяется когда файл попал в репозиторий по ошибке и его нужно оставить локально но добавить в `.gitignore`.

**`-f` (force)** — по умолчанию Git не позволит удалить файл с незакоммиченными изменениями. Это защитный механизм — если бы Git удалил файл сразу, последние изменения стёрлись бы из рабочей директории и восстановить их средствами Git было бы невозможно: база данных Git о них просто не знает.

Флаг `-f` буквально говорит Git: *"Я знаю что делаю, сотри это немедленно"*. Файл удаляется и из индекса и с диска. Из корзины его тоже не достать — удаление происходит на уровне терминала.

> **Нюанс:** если файл вообще ни разу не добавлялся в индекс (статус `untracked`) — `git rm` его просто не увидит. Для удаления таких файлов используется `git clean -f`.

## 2. Переименование файлов

С точки зрения Git **переименования как отдельной операции не существует**. Git воспринимает переименование как два действия: удаление старого файла и создание нового.

### Как это выглядит при ручном переименовании

```bash
mv app.py application.py

git status
# Changes not staged for commit:
#   deleted:  app.py       ← старый файл удалён
# Untracked files:
#   application.py         ← новый файл не отслеживается
```

После того как добавишь оба изменения в индекс — Git вычислит хеши файлов. Если содержимое совпадает, Git поймёт что это было переименование:

```bash
git add .

git status
# Changes to be committed:
#   renamed: app.py -> application.py   ← Git распознал переименование
```

### Команда git mv

`git mv` — удобный способ переименовать файл за один шаг. Одновременно переименовывает файл в рабочей директории и добавляет изменение в индекс:

```bash
git mv <старое_имя> <новое_имя>

# Пример
git mv app.py application.py

git status
# Changes to be committed:
#   renamed: app.py -> application.py
```

## 3. Важные концепты

**Сохранность данных** — Git хранит всю историю. Если файл был удалён в последнем коммите — он всё равно остаётся в истории репозитория и его можно восстановить.

**Безопасность при удалении** — Git выдаст ошибку при попытке удалить через `git rm` файл с незакоммиченными изменениями. Эти данные невозможно будет восстановить из репозитория после удаления — Git защищает от случайной потери работы.

**Глобальный .gitignore** — личные настройки редакторов (`.idea/`, `.vscode/`) лучше прописывать в глобальном файле игнорирования на своей машине, а не в `.gitignore` проекта.

Сначала создаёшь файл `~/.gitignore_global` и записываешь туда что хочешь игнорировать глобально, затем указываешь Git где этот файл находится:

```bash
git config --global core.excludesfile ~/.gitignore_global
```

Файл хранится в домашней директории (`~`) — рядом с `~/.gitconfig`. После этого Git игнорирует эти файлы во **всех** репозиториях на машине.

Разделение простое:

- **Глобальный `~/.gitignore_global`** — личные вещи которые касаются только твоей машины: `.idea/`, `.vscode/`, `.DS_Store`, `*.swp`. Не нужно прописывать в каждом проекте.
- **Локальный `.gitignore` в проекте** — вещи которые касаются проекта и должны игнорироваться у всей команды: `.env`, `node_modules/`, `dist/`, `*.log`.

### Шпаргалка

```bash
git rm <file>            # удалить файл везде (с диска и из индекса)
git rm -r <dir>          # удалить директорию рекурсивно
git rm --cached <file>   # перестать отслеживать, сохранив файл локально
git rm -f <file>         # принудительное удаление
git mv <old> <new>       # переименовать файл
```
