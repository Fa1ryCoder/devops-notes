# 3.11 Git – Ветки – История переключений веток: лог ссылок reflog

## Что такое reflog

Reflog (reference log) — это журнал, в который Git локально записывает каждое изменение ссылок: HEAD и указателей веток. Переключение на другую ветку, коммит, слияние, `reset`, `rebase` — любая операция, двигающая HEAD или ветку, добавляет в reflog новую запись.

Это принципиально не то же самое, что `git log`. `git log` показывает цепочку родителей — историю коммитов, до которых можно дойти от текущей точки, переходя от коммита к его родителю. Reflog показывает хронологию ваших собственных действий в репозитории, в том порядке, в котором они реально происходили, — независимо от того, остаются ли получившиеся коммиты достижимыми из текущих веток. Поэтому reflog продолжает помнить коммит даже тогда, когда он перестал быть частью истории какой-либо ветки: именно это и делает его инструментом восстановления.

Записи хранятся в `.git/logs/`. Лог HEAD — в файле `.git/logs/HEAD`, и в него попадает любое движение HEAD: переключения между ветками, коммиты на текущей ветке, слияния. У каждой ветки есть и свой собственный лог — в `.git/logs/refs/heads/<имя_ветки>` — но туда попадают только события, двигающие указатель именно этой ветки (коммиты, сделанные на ней, слияния в неё), а не переключения на неё и с неё: это движение самого HEAD, а не ветки.

Каждая строка в файле — одна запись:

```
d0a09971b458a258... 963d670401e98bba... Test User <test@example.com> 1704888000 +0000	commit: master: add line3
```

- хэш, с которого сдвинулись;
- хэш, на который сдвинулись;
- автор и e-mail;
- время коммита и таймзона;
- после таба — сообщение операции.

Это сообщение (`checkout: ...`, `commit: ...`, `merge ...`) и есть то, что видно в выводе `git reflog`.

## Основные команды

`git reflog` — самый частый вызов, показывает reflog для HEAD от новой записи к старой, индекс `0` — самая свежая. Это сокращение для `git reflog show`, а `show` без аргумента по умолчанию берёт именно HEAD — так что `git reflog`, `git reflog show` и `git reflog show HEAD` дают идентичный результат. Под капотом это тот же движок, что и у обычного `git log`: `git log -g --oneline` на тех же данных даёт побайтово идентичный вывод, флаг `-g` просто переключает источник с истории коммитов на reflog.

```
$ git reflog
963d670 (HEAD -> master) HEAD@{0}: checkout: moving from feature to master
b50977e (feature) HEAD@{1}: checkout: moving from master to feature
963d670 (HEAD -> master) HEAD@{2}: commit: master: add line3
```

Имена в скобках рядом с хэшем — декорирование, ровно как у `git log --decorate`: какие ссылки прямо сейчас указывают на этот коммит. Это не часть самой записи, а информация, которую Git подставляет заново при каждом выводе, глядя на текущее состояние ссылок. Поэтому если ветку удалить, её имя пропадёт из всех последующих выводов reflog, а сама строка с хэшем и сообщением останется на месте.

`git reflog <имя_ветки>` показывает не HEAD, а reflog конкретной ветки — только записи, двигавшие её собственный указатель. Индексация работает по той же логике, но через имя ветки: `master@{0}`, `master@{1}` и так далее.

`git log -g --date=iso` — тот же обход reflog, но через полноценный `git log` со всеми его форматами:

```
$ git log -g --date=iso -1
commit 963d670401e98bba7ae90cd9e5f9f79ec8101772
Reflog: HEAD@{2026-08-06 08:32:39 +0000} (Test User <test@example.com>)
Reflog message: checkout: moving from br-a to master
Author: Test User <test@example.com>
Date:   2024-01-10 12:00:00 +0000

    master: add line3
```

`--date=iso` здесь переформатирует именно дату коммита (строка `Date:`), а не момент самой reflog-записи — его Git показывает отдельно, в строке `Reflog:`.

## Адресация записей: `@{n}` и `@{дата}`

Пока запись жива в reflog, к соответствующему состоянию можно обратиться напрямую: `<ссылка>@{n}` — по индексу, или `<ссылка>@{"дата"}` — по времени. В роли `<ссылка>` — обычно `HEAD`, но подходит и имя ветки со своей индексацией.

По индексу: `HEAD@{6}` — состояние 6 записей назад. По дате: `HEAD@{"2023-10-10 12:00:00"}`; кавычки обязательны, если в дате есть пробел, иначе shell разобьёт её на два аргумента, а в ISO-формате с `T` вместо пробела (`HEAD@{2023-10-10T12:00:00}`) кавычки не нужны. Если точного совпадения нет, Git берёт ближайшую запись, но не позже указанного момента.

Запись вида `<ссылка>@{n}` или `<ссылка>@{"дата"}` принимает любая команда, ожидающая коммит, — не только `git log` или `git show`, но и, например, `git branch`. Если в `git reflog` видно `b50977e HEAD@{4}: commit: feature: add line2`, а ветка `feature`, на которой сделан этот коммит, уже удалена, — `git branch feature HEAD@{4}` (или напрямую `git branch feature b50977e`) вернёт её на то же место.

## Быстрое переключение между ветками

`git switch -` переключает на ветку, на которой вы были непосредственно перед текущей. Вызванная второй раз подряд, она возвращает обратно — перекидывает между двумя последними ветками туда-сюда. `git switch @{-1}` — то же самое явной записью, а `git switch @{-n}` — на n переключений назад: `@{-2}` — ветка, на которой вы были за два переключения до текущего момента.

Механика та же, что и у остальных возможностей reflog: Git ищет в reflog HEAD последнюю запись со словом `checkout` в сообщении и переключает туда, откуда было совершено это переключение. Слово «checkout» здесь — не название команды, а обозначение типа операции в самом сообщении reflog; оно не меняется от того, что переключение сделано через `switch`.

## Локальность и срок хранения

Reflog целиком локален: он лежит в `.git/logs/` рядом с остальными служебными файлами репозитория и не входит в то, что передаётся по сети. При `git push` на сервер уходят только объекты и ссылки на ветки — `.git/logs/` там не появляется вообще. Из этого следует, что у каждого, кто работает с репозиторием, reflog свой: он отражает историю именно локальных действий, и коллеги его не видят, а вы не видите их.

Записи не хранятся вечно — их удаляет `git gc`, вручную или автоматически. По умолчанию: 90 дней для записей, чьи коммиты всё ещё достижимы через какую-то ветку (`gc.reflogExpire`), и 30 дней — если коммит уже недостижим, например после удаления ветки (`gc.reflogExpireUnreachable`). Оба значения настраиваются в конфиге.
