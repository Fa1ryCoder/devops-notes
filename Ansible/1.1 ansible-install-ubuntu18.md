# 1.1 Изолированная установка Ansible на кассовый сервер (Ubuntu 18.04 LTS)

## Зачем отдельная инструкция для Ubuntu 18.04?

Ubuntu 18.04 (Bionic) использует Python 3.6.9. Свежие версии Ansible его не поддерживают — попытка поставить последний Ansible без учёта этого сломает установку. Поэтому здесь жёстко фиксируется версия `ansible==4.10.0` (ядро `ansible-core 2.11`) — это последний стабильный релиз с официальной поддержкой Python 3.6.

В остальном принцип тот же что и в Документе 1: всё ставится изолированно через `pipx`, системный Python не трогается.

---

## Архитектура безопасности

Три уровня защиты, которые гарантируют что установка не уронит прод:

**1. Никакого sudo для Python-пакетов** — все утилиты и библиотеки ставятся без прав суперпользователя. Они физически не могут получить доступ к системным файлам Python.

**2. Изоляция через pipx** — каждый инструмент ставится в собственное выделенное окружение (`~/.local/pipx/venvs/`). Зависимости Ansible никогда не пересекутся с зависимостями других утилит и системного софта кассы.

**3. Фиксация версии** — жёстко указываем `ansible==4.10.0`, совместимый с Python 3.6. Более свежая версия без фиксации сломала бы окружение.

---

## Шаг 1. Подготовка бинарных зависимостей

Для сборки модулей шифрования (`cryptography`) Ansible требуются компиляторы и заголовки библиотек. Устанавливаем их через `apt` — эти пакеты никак не влияют на уже запущенные Python-скрипты:

```bash
sudo apt update
sudo apt install -y python3-pip python3-venv build-essential libssl-dev libffi-dev python3-dev
```

---

## Шаг 2. Обновление pip в пространстве пользователя

В репозиториях Ubuntu 18.04 лежит устаревший `pip 9.0.1` — он не умеет работать с современными репозиториями и часто ломает установку сложных зависимостей. Обновляем его строго локально для текущего пользователя (флаг `--user`), не затрагивая общесистемный бинарник:

```bash
python3 -m pip install --user --upgrade pip

# Проверка — версия должна стать выше 21.x
python3 -m pip --version
```

---

## Шаг 3. Установка и настройка pipx

```bash
# 1. Устанавливаем pipx в пользовательское пространство
python3 -m pip install --user pipx

# 2. Добавляем ~/.local/bin в конфигурацию шелла (.bashrc)
python3 -m pipx ensurepath

# 3. Перечитываем конфиг текущей сессии
source ~/.bashrc

# 4. Проверяем что pipx подхватился из домашней директории
which pipx
# Ожидаемый вывод: /home/имя_пользователя/.local/bin/pipx
```

**Важно:** на Ubuntu 18.04 `pipx` устанавливается через `python3 -m pip install --user pipx`, а не через `apt` — в репозиториях Bionic его нет.

---

## Шаг 4. Установка Ansible

```bash
pipx install ansible==4.10.0
```

⚠️ **Без флага `--include-deps`** — в отличие от Ubuntu 20.04+, на 18.04 этот флаг может притащить в глобальный `PATH` бинарники старых версий библиотек и создать конфликты с другими консольными инструментами. Здесь он не нужен.

⚠️ **На этапе установки** пакет `cryptography` компилируется из исходников — процессор может быть загружен на 100% в течение 3–5 минут. Это нормально.

---

## Шаг 5. Проверка установки

```bash
ansible --version
```

Ожидаемый результат:
```
ansible [core 2.11.12]
  ansible python module location = /home/.../.local/pipx/venvs/ansible/...
```

**Критически важно:** строка `ansible python module location` должна вести строго внутрь домашнего каталога (`/home/.../.local/pipx/venvs/ansible/...`), а не в `/usr/`. Это подтверждает что системный Python не тронут.

**Smoke-тест** — проверка инициализации движка без сетевых пакетов:

```bash
ansible localhost -m ping
```

Ожидаемый ответ:
```json
localhost | SUCCESS => {
    "changed": false,
    "ping": "pong"
}
```

---

## Траблшутинг

**`pipx: command not found` после `source ~/.bashrc`**

Причина: работаете в другом шелле (zsh, tmux-сессия и т.д.).

Решение — добавить путь вручную в текущую сессию:
```bash
export PATH="$HOME/.local/bin:$PATH"
```

**В системе уже стоит Ansible из apt**

Причина: кто-то ранее выполнил `sudo apt install ansible`. Системный пакет перехватывает команды.

Решение — удалить системный пакет (плейбуки и роли при этом не пострадают):
```bash
sudo apt purge -y ansible
sudo apt autoremove -y
```

---

## Шпаргалка по управлению через pipx

```bash
pipx list                   # Посмотреть список изолированных утилит
pipx reinstall ansible      # Пересобрать окружение Ansible с нуля
pipx uninstall ansible      # Полное бесследное удаление Ansible из системы
```

---

## Итоговый чек-лист

```bash
# 1. Ставим зависимости для сборки
sudo apt update && sudo apt install -y python3-pip python3-venv build-essential libssl-dev libffi-dev python3-dev

# 2. Обновляем pip локально
python3 -m pip install --user --upgrade pip

# 3. Ставим pipx
python3 -m pip install --user pipx
python3 -m pipx ensurepath
source ~/.bashrc

# 4. Ставим Ansible с фиксацией версии
pipx install ansible==4.10.0

# 5. Проверка
ansible --version
ansible localhost -m ping
```
